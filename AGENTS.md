# Startpage - Agent Instructions

Local implementation details live in code comments; this file records cross-cutting invariants, commands, and pointers.

## Project Overview

Lightweight YouTube feed startpage built with Svelte 5 + Vite, using Piped API or YouTube.js backend for fetching channel videos. Deployed to GitHub Pages.

## Commands

- `npm ci` - Install frontend dependencies (Node 26, matching CI)
- `npm run dev` - Start dev server
- `npm run build` - Production build (output: `dist/`)
- `npm run preview` - Preview production build locally
- `npm run check` - `svelte-check` for the app, then `tsc -p tsconfig.node.json` for the Vite/constants config (the latter is `composite` and regenerates the gitignored `src/constants.d.ts`)
- `npx vitest run` - Run the test suite once (CI runs `npm test`, which is `vitest` and starts watch mode in a TTY)
- `npx vitest run tests/feed.test.ts` - Run one test file; add `-t "<name>"` to filter by test name
- `npx prettier --write .` - Format the codebase
- `npx prettier --check .` - Check formatting

### Deno alias

`deno task <name>` is an alias for the same `package.json` scripts (`dev`, `build`, `preview`, `check`, `test`); the toolchain (`vite`, `vitest`, `svelte-check`) still runs under Node. Use `deno task test --run` when using Deno, because `deno task test` starts Vitest in watch mode. Only `scripts/healthcheck.ts` is native Deno (`deno run`, JSR). A full Deno-runtime migration is not feasible (vitest `.svelte` imports via Vite, `svelte-check` typechecker, `wrangler` backend, Node-based CI/Docker).

### Definition of done

Before finishing a change, run:

`npm run check && npx vitest run && npx prettier --check .`

### Generated files

Do not hand-edit generated output:

- `src/constants.d.ts`, `vite.config.d.ts` - emitted by `npm run check` (gitignored)
- `startpage-api/worker-configuration.d.ts` - generated by `npx wrangler types` (tracked)
- `dist/` - build output (gitignored)

Do not deploy or push unless the user asks.

## Architecture

### Entry Points

- `src/main.ts` - Mounts `App.svelte`
- `src/App.svelte` - Router (navaid), global state subscriptions, service worker registration, settings overlay, dock
- `src/config.ts` - App-level config (base path `/startpage`, search delay, etc.)

### Layout

- No top navigation bar. `Home.svelte` shows the three main columns (Channels, Bookmarks, Feeds); below the `xl` breakpoint only the selected column is shown with a bottom tab bar.
- All three columns use `Column.svelte`: compact header with title + header actions + `+` toggle, an optional collapsible form snippet, and a scrollable body.
- Shared control primitives (`.column__*`, `.button`) live in `src/app.scss` because they are used across component scopes.
- `Dock.svelte` is the fixed bottom-right entry point for the floating search palette and settings (mouse/touch access alongside keybinds).
- `SearchPalette.svelte` renders only when `app.searchOpen` is true; it is mounted globally in `App.svelte`.

### State Management

- **`src/share/config.ts`** - `config` store (writable), `Config` class extends `LocalStorage`
- **`src/share/status.ts`** - `status` store (writable), `Status` class extends `LocalStorage`
- **`src/share/channels.ts`** - `channels` store (`Map<string, Channel>`) + memory-only `channelStates` (`{ error }` per channel id from the latest fetch; loading comes from `status.feed.fetching.now`), `Channels` class extends `LocalStorage`
- **`src/share/bookmarks.ts`** - `bookmarks` store (`Map<string, Bookmark>`), `Bookmarks` class (manual localStorage sync, NOT `LocalStorage`)
- **`src/share/feeds.ts`** - `feeds` store (`Map<string, Feed>`, Atom/RSS subscriptions persisted as `[url, Feed][]`) + in-memory `entries` and `feedStates` caches, `Feeds` class extends `LocalStorage`
- **`src/lib/state/app.svelte.ts`** - `$state` app object (`route`, `filter`, `feedFilter`, `searchOpen`)

### LocalStorage Pattern

- Subclasses of `LocalStorage` must define `static LS_NAME = 'name'` (the base throws if it is undefined)
- `LocalStorage.get()` returns `undefined` on parse error (graceful degradation)
- `saveOnUpdate()` subscribes store to persist on every change
- `Bookmarks` uses its own `subscribeToLocalStorage()` with Map serialization

### Store validation

- Stored and imported data is untrusted: every store has one total parser (`parseBookmarks`, `Channels.parseStored`, `Feeds.parseStored`, `parseConfig`, `parseStoredStatus`). It never throws; malformed entries are skipped and missing fields degrade to defaults. `src/util/validate.ts` holds the shared shape helpers.
- The same parser backs module-scope hydration (lenient: a corrupt array must not brick boot) and `restore`/import (strict: an `issues` array reports what was malformed).
- A missing or empty channel `url` is valid legacy data - do not reject it (that deletes channels on boot). `Channels.parseStored` explains how `#refFor` resolves the kind from the map key.
- `SettingsGeneral.importConfig` validates every section before applying any of them and rejects the whole payload when `issues` is non-empty, so a malformed payload never half-applies or reaches a store. Absent sections are left untouched.
- Numeric config fields in `parseConfig` must be integers; `readCount` in `src/share/config.ts` owns the fallback and clamping rules.
- `buildConfigFile()` (`src/share/config-file.ts`) builds exports through the same parsers, so an export always re-imports.

### Routing

- Uses `navaid` (client-side router)
- Routes defined in `src/routes.ts`
- Settings is a single-page overlay at `/settings` (`Settings.svelte` wrapping `SettingsGeneral`). The old `/settings/channels` and `/settings/bookmarks` URLs redirect to `/settings`.
- Settings renders as a modal overlay over a still-mounted `Home`; close (button, `Escape`/configured close key, backdrop) navigates home. Deep links still work because the real route is preserved.
- GitHub Pages SPA fallback: `public/404.html` stores path in localStorage, read by `src/util/github.ts`

### Key Components

- `SearchPalette.svelte` - Floating channel search/add palette, opened by the configurable `s` keybind or the dock; searches via the active backend, adds channel/playlist URLs, closes after adding
- `Column.svelte` - Shared compact column shell (header, actions, add toggle, form slot, scrolling body)
- `Channels.svelte` - Video feed column; calls `Channels.refetch()` on mount, inline channel URL add form
- `FilterDropdown.svelte` - Shared header dropdown used by both feed columns (toggle button, "All" row, rows with inline rename and remove, optional loading/error state square; failing items also put a red square on the collapsed toggler)
- `ChannelsFilter.svelte` - Thin wrapper passing channels (with fetch errors from `channelStates` and loading from `status.feed.fetching.now`) to `FilterDropdown`
- `ChannelsSync.svelte` - Header sync button
- `Bookmarks.svelte` - Bookmarks column grouped by tag, inline add form, inline edit form (name/tag/URL via right-click or long-press), per-entry remove
- `Feeds.svelte` - Atom/RSS reader column; merges entries from all subscriptions and filters by feed via `FilterDropdown` in the header. Parsing lives in `src/util/feed.ts` (Atom, RSS 2.0, RSS 1.0/RDF); summaries are text-only and hidden unless `feedShowSummary` is enabled. Per-feed loading/error state appears in the dropdown and on the collapsed toggler; selecting a failing feed shows its error in the entries area.
- `Dock.svelte` - Fixed search/settings buttons (also handles the `,` settings keybind)
- `Closeable.svelte` - Wrapper for dropdowns/menus, closes on configurable key (default Escape) or click-outside, has `onClose` callback

### Backend (API Strategy)

- Two API sources: **Piped API** (public instances) and **startpage-api** (YouTube.js deployed on Cloudflare Worker in `startpage-api/`)
- **Worker work:** read `startpage-api/AGENTS.md` before changing the worker; install its dependencies with `npm ci --prefix startpage-api`. Worker tests live in the root `tests/` and run with the root Vitest command.
- `src/lib/api/backend.ts` - `Backend` interface, `backends` record mapping keys to classes, `backend` derived store
- Each backend class has `static name = '<name>' as const` - the single source of truth for its identifier
- `BACKEND_TYPES` / `InstanceType` / `isInstanceType` live in `src/lib/api/backend-types.ts` (a leaf module, avoiding a `config.ts` cycle); `backends` is typed `Record<InstanceType, …>`, so the compiler enforces parity.
- `SettingsGeneral.svelte` maps `InstanceType` → UI labels via `backendLabel` record
- **Rate budget:** one shared `FEED_LIMIT` binding in `startpage-api/wrangler.jsonc` throttles every worker route. A page load fires one request per channel plus one per feed in parallel - there is deliberately no client-side pacing. `Channels.refetch`/`Feeds.refetch` are single-flight; non-reload callers join the run in flight and a `reload: true` call is chained after it. Do not add pacing without checking the worker budget.
- **Browser caching:** worker listings (`/channels`, `/playlists`) carry a private max-age; `StartpageBackend` sends `cache: reload ? 'reload' : 'default'`, so sync or an expired local lifetime bypasses the browser cache. Keep the worker TTL and the default `cacheLifetimeInMinutes` in sync. The SW does not participate: it is precache-only.

Adding a new backend:

1. Create `src/lib/api/<name>-backend.ts` with `class <Name>Backend implements Backend { static name = '<name>' as const }`
2. Add `'<name>'` to `BACKEND_TYPES` in `src/lib/api/backend-types.ts` and the import + entry to `backends` in `backend.ts` (compile fails if the two disagree)
3. Add UI label to `src/share/strings.ts`
4. Add the backend to `tests/backend-contract.test.ts` (`CASES` plus its route adapter) so the shared contract suite covers it
5. Add label entry in `SettingsGeneral.svelte` `backendLabel` map
6. If it needs unique config fields, add an `{#if}` block in the settings template

### SCSS

- Variables: `src/lib/scss/_variables.scss` (gaps, z-index, typography scale, etc.)
- Every `font-size` comes from the `$font-size-*` scale in `_variables.scss`; do not hardcode sizes.
- Themes: `src/lib/scss/_themes.scss` (Gruvbox color palette)
- Breakpoints: `src/lib/scss/_breakpoints.scss`
- Mixins: `src/lib/scss/_mixins.scss` (`line-clamp`, `input-base`)
- All text-entry controls include `input-base` (`_mixins.scss`); contexts only add sizing and error/disabled variants.
- Components use `@use 'scss/variables' as *;` (Vite resolves via `src/lib/scss/`)
- Global layout/control primitives live in `src/app.scss` (`Column` chrome form controls, `.button`)

## Important Conventions & Quirks

### Inline editing

- Editable labels use the `editGesture` action (`src/lib/gestures.ts`): right-click on desktop or long-press on touch; a plain click keeps its primary action.
- Single-field renames use the `inlineRename` action (`src/lib/inline-rename.ts`): Enter/blur saves, Escape cancels.
- Bookmarks edit name, tag, and URL inline; URL changes go through `Bookmarks.replace()`.

### Content Security Policy

- `vite.config.js` `csp()` injects a strict `<meta http-equiv="Content-Security-Policy">` at build time (GitHub Pages cannot set response headers). See `csp()` for the exact policy; it is `'self'` by default, with `https:` allowed for images and connections.
- **Invariant:** no inline `<script>`/`<style>` or `style="..."` in markup, no external fonts/CDNs, and no new origins. `img-src`/`connect-src` allow `https:` deliberately (thumbnails and the API); everything else is `'self'`. Svelte's `style:` directive sets styles through CSSOM and is fine.
- The plugin is `apply: 'build'`, so `vite dev` will not catch a violation. Verify with `npm run build && npm run preview`.

### Service Worker

- `src/sw.js` - built by Vite from `vite.config.js` `build.rollupOptions.input` (the `sw` entry) and `output.entryFileNames` (SW stays at `sw.js`, other entries go to `assets/[name].js`) to keep scope at `/startpage/sw.js`. Registered in `src/App.svelte` behind the `import.meta.env.PROD` guard, because `vite dev` does not serve the bundled SW. Do not move the SW under `assets/`.
- `vite.config.js` output names are **intentionally without `[hash]`**: the `install` precache list in `src/sw.js` hard-codes those filenames. **Invariant:** re-enabling hashing or adding chunks requires updating that manifest (or switching to a generated manifest).
- `VERSION` in `src/sw.js` comes from `VITE_GIT_COMMIT` with no fallback and must be set at build (the `Build project` step in `.github/workflows/deploy.yml`).
- **Cache namespacing:** Cache Storage is per-origin and GitHub Pages project sites share `<user>.github.io`, so `CACHE = 'startpage-' + VERSION` and activation deletes only keys with `CACHE_PREFIX`. **Invariant:** never delete origin-wide, and keep the prefix constant for this app.
- The SW is **precache-only**: the `fetch` handler only serves install-time entries and never caches network responses. Runtime/API caching is the browser HTTP cache's job; adding runtime caching here would defeat `reload` unless it explicitly checks `request.cache`.

### Atom/RSS reader (CORS)

- `feedProxyUrl` in `src/share/config.ts` defaults to the `startpage-api` worker. Requests become `<feedProxyUrl>/feed?url=<encoded feed URL>`; an empty value means direct `fetch`, which only works for feeds that send `Access-Control-Allow-Origin` (many blogs do not).
- `startpage-api/src/feed-proxy.ts` implements `GET /feed?url=`. It returns raw XML so the frontend remains the only parser, allows only XML feed content types, and is SSRF-hardened: it blocks local/private hosts and every redirect target. See the file for size, timeout, and redirect limits.
- Feed metadata is persisted; parsed entries are memory-only and re-fetched per `cacheLifetimeInMinutes` (`reload` bypasses it). Entries across feeds are deduped by URL and capped by `readerLimit`.
- Feed summaries are stripped to plain text deliberately - do not switch to `{@html}` without a sanitizer.
